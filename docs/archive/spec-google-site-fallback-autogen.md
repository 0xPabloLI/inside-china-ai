# Spec: #88 Part 2 — Universal Google `site:` Fallback Auto-Generation

## Problem Statement

When CDP fails for a source, the fallback chain currently goes: API → CDP → `googleSiteFallback` (if configured) → `mcpFallback` (if configured). But only `x_search` has an explicit `googleSiteFallback` config — the other 46 sources with `capabilities.articles` have no Google `site:` fallback at all. When CDP fails for these sources, they go straight to MCP fallback (if configured) or return empty results, missing the intermediate Google `site:` search layer that could rescue results.

## Solution

Auto-generate `googleSiteFallback` for applicable sources at registry load time (in `enrichWithCapabilities()`). Sources without an explicit `googleSiteFallback` that meet applicability criteria get an auto-generated one derived from their `url` domain. The auto-generated config uses a shared Google `h3` extractor script and constructs a `site:domain.com keyword` search URL.

### Applicability Criteria (Exclusion List)

Auto-generation is skipped for sources that:
1. Already have explicit `googleSiteFallback` (override path — X search keeps its own config)
2. Have `apiSearch` (API sources — if API fails, site is down, Google won't help)
3. Have `mcpFallback` (MCP is more precise than Google `site:`)
4. Are search engines themselves (google_news, bing_news, baidu_search, etc.)
5. Are image/asset libraries (pexels, unsplash, etc. — Google `site:` doesn't return images)
6. Are special cases (datacube_ai RSS, wechat_dongchabeating uses Google as primary, weibo_hot is hot search)

**13 sources qualify for auto-generation**: qbitai, jiqizhixin, 36kr, techcrunch, bloomberg, guancha, ithome, xinhua, thepaper, leiphone, xinzhiyuan, zhidx, zhihu.

### CDP Test Results (2026-08-28)

All 13 applicable sources tested with Google `site:domain.com DeepSeek`:
- **12/13 returned results** (9-10 articles each, h3-based extraction)
- **1 EMPTY**: xinzhiyuan (www.xinzhiyuan.com returns 403/timeout — site appears down, Google has no index). Auto-gen still applies; empty result degrades gracefully to next fallback layer.
- **0 anti-bot/captcha** — Google did not block any search
- **Bloomberg**: paywall does not affect search result page extraction (titles visible on Google results page)
- **No domain filter needed**: Google `site:` search only returns results from the specified domain

## User Stories

1. As a trend discovery user, I want sources to have Google `site:` fallback automatically, so that when CDP fails I still get results from Google's index of that site.
2. As a research mode user, I want homepage-only sources (qbitai, 36kr, techcrunch, etc.) to be included in research mode, so that I can find articles from these sites even though they don't support keyword search natively.
3. As a pipeline developer, I want the auto-generation to happen at registry load time, so that `collectFromSource()` doesn't need changes — the `googleSiteFallback` field is already populated.
4. As a pipeline developer, I want sources with explicit `googleSiteFallback` to keep their own config, so that X search's domain filter and custom script are preserved.
5. As a pipeline developer, I want a shared `h3` extractor script, so that I don't need to write per-source Google search scripts.
6. As a pipeline developer, I want the exclusion logic to be testable, so that I can verify which sources get auto-generated fallback and which don't.
7. As a trend discovery user, I want sources whose sites are down (like xinzhiyuan) to still have auto-gen fallback, so that if the site comes back online the fallback works without code changes.
8. As a research mode user, I want the research mode filter to automatically include sources with auto-generated `googleSiteFallback`, so that homepage-only sources contribute to research results.

## Implementation Decisions

### 1. Auto-generation location: `enrichWithCapabilities()` in `source-registry.mjs`

Auto-generation happens at registry load time, not at runtime. This means:
- `enrichWithCapabilities()` injects `googleSiteFallback` into `capabilities.articles` for applicable sources
- `collectFromSource()` in `search-sources.mjs` requires **no changes** — Step 2 already checks `if (articles.length === 0 && googleSiteFallback)`
- The `googleSiteFallback` field in `capabilities.articles` is populated from either explicit source config OR auto-generation

### 2. Auto-generation function: `autoGenerateGoogleSiteFallback(source)`

New function in `source-registry.mjs`:
- Extracts domain from `new URL(source.url(testKeyword)).hostname`
- Returns `{ url: (keyword) => googleSiteUrl, articleScript: SHARED_GOOGLE_SITE_SEARCH_SCRIPT }` or `null` if URL not parseable
- Returns object with `_autoGenerated: true` flag for testing/debugging (not consumed by downstream)

### 3. Shared Google h3 extractor: `SHARED_GOOGLE_SITE_SEARCH_SCRIPT`

A generic Google search results extractor stored as a constant in `source-registry.mjs`:
- Selects all `<h3>` elements
- For each `h3`, finds the closest `<a>` ancestor or sibling
- Returns `[{ title, url }]`
- No domain filter (Google `site:` already filters by domain)

### 4. Exclusion function: `shouldAutoGenGoogleSiteFallback(source)`

New function in `source-registry.mjs`:
- Returns `true` if source should get auto-generated `googleSiteFallback`
- Returns `false` for: has `apiSearch`, has `mcpFallback`, has explicit `googleSiteFallback`, is search engine, is image library, is special case
- Exclusion list is a hardcoded set of source names

### 5. `enrichWithCapabilities()` modification

In the `capabilities.articles` construction block, after setting `googleSiteFallback: source.googleSiteFallback`:
```javascript
googleSiteFallback: source.googleSiteFallback || autoGenerateGoogleSiteFallback(source),
```
If source has explicit config, use it. Otherwise, auto-generate (which may return `null` for excluded sources, leaving `googleSiteFallback` as `null`/`undefined`).

### 6. Research mode filter: no changes needed

Current filter: `s.capabilities?.articles?.supportsKeyword || s.capabilities?.articles?.googleSiteFallback`. After auto-gen, applicable sources with `supportsKeyword: false` (qbitai, 36kr, techcrunch, bloomberg, guancha) will have `googleSiteFallback` populated, so they'll be included in research mode automatically.

### 7. 36kr/guancha/techcrunch upgrade: OUT OF SCOPE

Upgrading these sources to `supportsKeyword: true` (adding search URLs + articleScripts) requires CDP testing of their search pages and is a separate task. Auto-gen works regardless of `supportsKeyword` value.

### 8. Bloomberg paywall: no exclusion

Bloomberg's Google `site:` fallback works — search result page titles are visible. Paywall only affects article detail pages, not search results. No exclusion needed.

## Testing Decisions

### Test seam: `source-registry.test.mjs` + `source-registry-capabilities.test.mjs`

Existing test files are the highest seam. No new test files needed.

### Test cases (mapped from Scenario Matrix):

1. `autoGenerateGoogleSiteFallback(source)` returns object with `url` function and `articleScript` string for a source with parseable URL
2. `autoGenerateGoogleSiteFallback(source)` returns `null` for a source with unparseable URL
3. `SHARED_GOOGLE_SITE_SEARCH_SCRIPT` contains `h3` selector and `return results`
4. `SHARED_GOOGLE_SITE_SEARCH_SCRIPT` does NOT contain domain filter (no `x.com`, `twitter.com`, etc.)
5. `shouldAutoGenGoogleSiteFallback(source)` returns `true` for applicable sources (qbitai, ithome, etc.)
6. `shouldAutoGenGoogleSiteFallback(source)` returns `false` for excluded sources (API sources, MCP sources, search engines, image libraries, x_search)
7. `enrichWithCapabilities()` injects `googleSiteFallback` for applicable sources
8. `enrichWithCapabilities()` does NOT inject `googleSiteFallback` for excluded sources (still `undefined`)
9. X search keeps its explicit `googleSiteFallback` (not replaced by auto-gen)
10. Auto-generated `googleSiteFallback.url(keyword)` produces correct Google `site:domain.com keyword` URL
11. Auto-generated `googleSiteFallback` in `capabilities.articles` is the same object as top-level
12. Sources with `supportsKeyword: false` and auto-gen `googleSiteFallback` are included in research mode filter
13. Auto-gen `googleSiteFallback` has `_autoGenerated: true` flag

## Out of Scope

- Upgrading 36kr/guancha/techcrunch to `supportsKeyword: true` (requires CDP testing of search pages)
- Bloomberg paywall bypass (#85 tracks republisher alternatives)
- Google redirect URL handling (if Google wraps links in redirect, handle in follow-up)
- Search API Pool (#65)
- `articleScript` auto-fallback when selector breaks (#66)
- Single-Visit Extraction (#114, done)
