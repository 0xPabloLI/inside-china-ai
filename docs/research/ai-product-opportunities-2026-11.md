## 一、直接对标竞品完整拆解

### 1. LabInsightX — 单次体检报告 AI 解读的"便利店"

**一句话定位**：上传一张体检报告 PDF → 60 秒返回"红绿灯"式指标解读 + 营养建议 + 给医生的问题清单。像抽血化验的"自动解读自助机"，单次付费、无需订阅。

| 维度 | 事实 |
|---|---|
| **官网** | https://www.labinsightx.com |
| **成立时间** | 2026 年 4 月（TrustMRR 记录），创始人 Sajjad Ahmad，巴基斯坦 |
| **团队规模** | 单人（创始人兼开发者） |
| **定价** | Free（每月 1 次）→ Single $3.99/次 → Pro $5.99/月（5 次/月）→ Annual $3.99/月（年付） |
| **真实收入** | **累计收入 $10，无活跃订阅，正在以 $1,000 出售**（TrustMRR，2026-11-13 核实，LemonSqueezy API 校验） |
| **技术栈** | Next.js + Tailwind + React / Anthropic Claude / Supabase / LemonSqueezy / Vercel / Resend / Cloudflare（TrustMRR 披露）|
| **差异化卖点** | ① 红绿灯式可视化（红=异常、黄=临界、绿=正常）；② 给医生的问题清单（帮穷人"假装准备充分"去问诊）；③ 可叠加 10 人/年的家庭计划 |
| **目标用户** | 去医院抽了血但不想排队问医生的人、出国体检的海外华人、孕妇（有孕早/中/晚三期专属 ranges） |
| **壁垒** | 极低——OCR + LLM + 模板就能做，数据来源是公开的临床指标参考区间 |
| **风险** | 医生可能不认可解读结果、数据隐私法规（HIPAA/数据安全法）、大厂（百度健康/腾讯健康）随时能抄 |
| **可信度声明** | 必须加"仅供参考，不构成医疗建议，如有异常请咨询医生" |

**给你的启示**：

- **⚠️ 定价不是"已验证"，只是"标过价"**：累计收入 $10、零订阅，说明 $3.99 这个价格从未被真实付费验证过。它的价值是**交互与信息架构的参考**（红绿灯、健康分、医生问题清单、复诊提醒），不是商业验证
- **"红绿灯可视化"是值得抄的交互**——把医学数字变成红黄绿三色，降低认知门槛
- **"给医生的问题清单"是情绪钩子**——不擅沟通的人最需要，愿意花钱换"安全感"
- **家庭计划是现成的 upsell**——一次买 10 人份，客单价直接翻倍

## 二、其他独立开发者 AI 产品案例（2025–2026 真实跑通）

这些案例验证了"单人/小团队 + AI 自动化"能做到的上限：

### A. Medvi — 4 亿美元 OPC 的启示

- **创始人**：Matthew Gallagher（单人 + 弟弟 Elliot = 2 人公司）
- **业务**：医疗/美容类 OPC（Online Patient Clinic）——患者线上填问卷 → AI 判断是否适合药物 → 医生远程开处方 → 邮寄
- **业绩**：2025 年销售额 $4.01 亿，净利润 $6500 万（**利润率 16.2%，是同赛道上市公司 Hims & Hers 的 3 倍**）
- **模式**：AI 写代码 + AI 设计素材 + AI 客服 → 只需要 2 个人管合规和医生对接
- **启示**：**单人公司在"医疗服务的 AI 辅助"方向上已经能做到亿级收入**——但需要合规资质（医生团队 + 平台备案）

### B. Pep AI — GLP-1 追踪 App

- **创始人**：Cedric Roberge（22 岁学生，单人）
- **业务**：专门帮用户追踪 GLP-1/肽类药物使用的 App（Ozempic/Wegovy/Semaglutide 等减重药物正在爆发）
- **业绩**：2026 年初上线 → 几个月到 **$60K MRR**
- **冷启动**：Reddit 一条帖子拿到前 100 用户（GLP-1 是 Reddit 最热 subreddit 之一 r/GLP-1 有 130 万成员）
- **启示**：**找一个正在爆发的细分人群**（GLP-1 使用者、健身补剂用户、马拉松跑者），他们有共同焦虑且愿意花钱

### C. CalBuddy — 本地化套利

- **创始人**：Tomer Cnaan（单人，以色列）
- **业务**：把美国的 Cal AI（拍照算卡路里）移植到以色列——Hebrew 界面 + 以色列食物数据库
- **业绩**：2025-06 上线 → 月 $1K → 4 月后 $20K → 2026-04 **$81K/月**（年化百万美元）
- **关键洞察**：美国的成功产品在以色列没人做；以色列广告成本只有美国的几分之一；找两个本地健身博主分 50% 佣金 → 用本地信任破局
- **启示**：**你不需要发明新东西——找一个在海外跑通、但中国还没有的 AI 产品，把它本地化**

### D. 独立开发者陈云飞 — "小猫补光灯"App

- **创始人**：陈云飞（完全没有编程经验，用 AI 编程工具做的）
- **业务**：纯色图片补光工具——小红书女性拍照需要纯色背景补光
- **业绩**：**1 小时开发 + 4 小时登顶付费榜**（App Store）
- **模式**：发现小红书需求 → 用 AI 工具写代码 → 上架 → 变现
- **启示**：**完全没有编程经验的人也能用 AI 工具做付费 App**——你的开发经验反而是优势

## 五、LabInsightX 逆向拆解（2026-11-13 补充）

### 5.1 它接受什么报告

官网只写 "Upload your lab report"，没有限定格式白名单；从样本页与同类产品（Spike API 等）的文档推断，业界通行口径是：

| 维度 | 实际支持范围 |
|---|---|
| 格式 | PDF 优先；图片（JPEG/PNG/HEIC/WEBP）也可 |
| 清晰度 | 300+ DPI 才能稳定 OCR；手机翻拍的歪斜/阴影图会掉准确率 |
| 报告类型 | 化验单（血液/尿常规/生化/甲功/血脂）——样本是 18 项 CBC 面板 |
| 不支持的 | 影像报告（CT/MRI/X 光）、病理报告、心电图——这些没有"数值 + 参考区间"结构 |

**普通中国体检报告能用吗？能，但有三道坎**：

| 坎 | 具体问题 | 解决成本 |
|---|---|---|
| **指标名映射** | 中文名（白细胞计数、谷丙转氨酶、尿酸）→ 标准指标 ID | 需要建 300–800 条中英对照字典，可人工 + LLM 生成后抽查 |
| **单位换算** | 血脂 mg/dL ↔ mmol/L、肌酐 mg/dL ↔ μmol/L、尿酸 mg/dL ↔ μmol/L | 20–30 条换算规则，必须写死在代码里，不能让 LLM 算 |
| **表格重建** | 体检报告常是「检验项目 / 结果 / 单位 / 参考范围 / 提示」五列，多层表头、跨页、合并单元格 | 这是最难的一步，也是 TextIn 这类商用解析器专门解决的问题 |

另外两种中国体检报告会直接让这类产品失效：

1. **只有结论没有明细**的总检报告（"血脂偏高，建议复查"）——没有数值就没法算健康分
2. **关键指标缺失**：你的情况需要的 24 小时尿钙、尿草酸、尿 pH，普通体检套餐通常不含 → **普通体检报告不足以精确指导草酸钙结石膳食**，只能做保守泛化

### 5.2 逆向：它的六段管线

从样本页的输出结构反推，它做的事可以完整还原成一条确定性管线：

```
PDF/图片
  → ① 文字层优先（PDF 有 text layer 就直接抽，不走 OCR）
  → ② OCR（无文字层时）
  → ③ 表格重建：指标名 / 实测值 / 单位 / 参考区间 / 异常标记
  → ④ 指标归一化（中文名 → 标准 ID，单位统一）
  → ⑤ 确定性判定：值 vs 区间 → 三色（normal / borderline / critical）
  → ⑥ LLM 生成叙述（不参与数值判断）
       ├─ 健康分 0-100
       ├─ 通俗解读
       ├─ 医生问题清单（3-5 条）
       ├─ 复诊提醒（按指南间隔）
       └─ 膳食方案（需用户额外输入：饮食偏好 + 国家）
```

**关键证据与推断**：

| 它展示的东西 | 怎么实现的 | 可信度 |
|---|---|---|
| 红绿灯三档 | 值 vs 区间，边界外一定比例内算 borderline | 高（样本明示 13 正常/3 临界/2 严重） |
| 健康分 74/100（18 项，2 严重 + 3 临界） | 扣分模型，试算 100 − 9×严重 − 3×临界 ≈ 73，接近 74；且样本说"改善 Ferritin 和维 D 可到 89+"，说明按指标加权而非均等扣分 | 中（公式未公开，可反推） |
| "Lower than 85% of women aged 30–40" | **需要人群分布数据（美国是 NHANES）**，不是 LLM 能编的 | 高——这是最难复制的一层 |
| 按年龄/孕期/儿童切换参考区间 | 区间表 × 人群分层（WHO/ACOG/AAP/NCBI） | 高（官网明示来源） |
| 膳食方案"强调/限制/一天示例" | 规则表 + 饮食偏好 + 国家菜系，LLM 只做文字组织 | 高（样本结构与输入字段吻合） |
| 复诊提醒（8/10/12 周） | 按指标查指南里的复查间隔表 | 高（样本给了三个不同间隔，说明是查表不是编） |
| "报告永不存储" | 内存处理不落库，只留元数据 | 无法验证，但技术上就是"不写 DB" |

**这套东西的真实难度排序**（从难到易）：

1. **人群百分位**（需要真实分布数据，中国没有公开等价于 NHANES 的免费数据集）
2. **表格重建**（千院千面）
3. **指标字典 + 单位换算**（体力活，但确定）
4. **指南规则库**（需要认真读文献，且要持续维护）
5. **LLM 叙述**（最容易，也最容易被误当成全部）

> 大多数人以为这类产品 90% 靠 LLM，实际相反：**90% 的工程在"不许 LLM 说话"的部分**。

### 5.3 它的产品缺口（对你就是机会）

它的膳食方案只问两个字段：**饮食偏好 + 国家**。没有问病程、合并症、用药、症状。

对你的场景直接失效：

- 肾结石（草酸钙）+ 胆囊切除 + 胆固醇偏高，是**三条互相冲突的饮食约束**（低草酸 / 低脂 / 高纤维且要控精制碳水）
- 它不知道你胆囊切了 → 可能给出"每天一把坚果 + 橄榄油煎三文鱼"这种高脂方案
- 它不知道你有结石 → 可能给出"菠菜 + 甜菜根 + 坚果"这种高草酸组合

所以**"多病共存约束消解"就是差异化的真正所在**，不是又一个红绿灯。

## 九、给你的本地方案（针对肾结石 + 胆囊切除 + 胆固醇）

### 9.1 架构原则：LLM 只做叙述，不做数值判断

这是这类系统唯一不能妥协的设计。数字必须由确定性代码算，LLM 只负责把算好的结果翻译成人话。否则一定会在某次升级后编出不存在的数值——这是医疗 AI 最常见的失效模式。

```
体检报告 PDF/图片
  ↓ ① 文字层优先，无则 OCR
  ↓ ② 表格重建 → {指标名, 值, 单位, 参考区间, 标记}
  ↓ ③ 中文指标归一 + 单位换算（纯代码，可单元测试）
  ↓ ④ 判定：值 vs 区间 → 绿/黄/红（纯代码）
  ↓ ⑤ 约束求解：多病共存 → 食物黑白名单（规则表，非 LLM）
  ↓ ⑥ LLM：把 ④⑤ 的结果写成解读 + 一周食谱 + 就医问题
  ↓ ⑦ 输出 Markdown / PDF，落本地 SQLite
```

### 9.2 你的三条约束怎么消解（真正的难点）

| 约束 | 来源 | 典型冲突 |
|---|---|---|
| 低草酸（草酸钙结石） | 菠菜、甜菜、坚果、可可、浓茶、大黄 | 与"高纤维、多蔬果"冲突 |
| 低脂（胆囊切除） | 油炸、肥肉、全脂奶、大量坚果 | 与"橄榄油/坚果护心"冲突 |
| 降 LDL（胆固醇） | 少饱和脂肪、多可溶性纤维 | 与"低草酸"部分冲突（坚果既降 LDL 又高草酸） |

消解原则（可作为规则表的第一版）：

1. **冲突时以"急性风险"优先**：结石绞痛 > 血脂长期风险 → 高草酸食物排黑名单
2. **同族替换而非禁止**：坚果 → 南瓜籽/核桃（草酸相对低）；菠菜 → 小白菜/芥蓝（低草酸高钙）
3. **烹饪可降低而非消除**：菠菜焯水 1 分钟可去约 30–50% 草酸（不同文献差异大，须标注区间而非单点）
4. **钙要和草酸同餐吃**：肠道内结合减少吸收——这条常被误解成"结石不能补钙"
5. **胆囊切除后脂肪要分散**：单餐脂肪上限比全天总量更重要

### 9.3 数据缺口清单（普通体检报告给不了的）

| 缺什么 | 为什么重要 | 怎么补 |
|---|---|---|
| 24h 尿钙 / 尿草酸 / 尿 pH | 决定结石类型与复发风险的唯一硬指标 | 医院专项检查，一年一次 |
| 胆囊切除时间 + 术后症状 | 决定脂肪耐受度 | 问卷 |
| 用药（利尿剂、钙片、维生素 C） | 大剂量 VC 促草酸钙结石 | 问卷 |
| 饮食日记 3 天 | 才知道你实际草酸摄入 | 自己记，或拍照记录 |
| 家族史 | 结石/血脂遗传倾向 | 问卷 |

### 9.4 落地顺序

1. **第 1 步（半天）**：`open-health` Docker 起本地实例，用你自己的报告跑通"上传 → 结构化 → 问答"，先看它表格重建的准确率
2. **第 2 步（2–3 天）**：抽 20–30 个你关心的指标，建中文指标字典 + 单位换算 + 区间判定，写成纯函数 + 单元测试
3. **第 3 步（2–3 天）**：把三条约束写成食物黑白名单规则表（先 100 种常见食物，标注草酸/脂肪/可溶性纤维三列）
4. **第 4 步（1 天）**：接本地 MLX 模型（Qwen3）生成叙述，输入只给结构化结果，禁止它读原始 PDF
5. **第 5 步**：拿你自己的历史报告做回测——同一指标跨年份趋势必须能对齐（不同医院区间不同，趋势图要带区间标签）

### 10.2 不要健康分，改做什么

健康分是把多维结果压成一个数字，代价是：不可解释、无法归因、用户不知道该改哪一条。替代方案：

| 替代物 | 长什么样 | 为什么更好 |
|---|---|---|
| **异常清单 + 每条一个动作** | "尿酸 520（参考 420）→ 本周先做：每天饮水 2.5L，减少动物内脏与浓肉汤" | 可执行、可验证 |
| **约束满足报告** | "本周方案已满足：草酸 < 目标、单餐脂肪 < 30g、膳食钙 1000–1200mg；未满足：膳食纤维差 5g" | 直接对应你要的"合理膳食" |
| **复测指标 + 时间点** | "8 周后复查尿酸、血脂四项" | 闭环 |

### 10.3 原则的出处（哪些是指南、哪些是我的工程判断）

| 原则 | 出处 | 证据强度 |
|---|---|---|
| 尿量 ≥ 2.5 L/天（钙结石） | AUA《Medical Management of Kidney Stones》2026 Part I：饮水使尿量 ≥2.5 L 或 85 oz（Moderate Recommendation, Grade C） | 强（指南） |
| 高草酸尿/高草酸血症者液体 3.5–4.0 L/天 | EAU Urolithiasis 指南（Primary Hyperoxaluria 章节） | 强（指南） |
| 膳食钙 1,000–1,200 mg/天，**不要限钙** | AUA 指南（Standard, Grade B）：高尿钙者限钠 + 膳食钙 1000–1200 mg/天；观察性研究一致显示膳食钙越高结石风险越低 | 强（指南） |
| 限钠（目标约 100 mmol/天 ≈ 2.3 g 钠） | AUA 指南 | 强（指南） |
| 减少高草酸食物（针对高尿草酸者） | AUA / EAU 均列为饮食管理项；但**没有统一的"每天多少 mg"上限** | 中（指南原则，无阈值） |
| 焯水可降可溶性草酸 30–87% | Chai & Liebman 2005（沸水 30–87%，蒸仅 5–19%）；巴基斯坦蔬菜研究（16–67%，菠菜最高 67%）；福建省卫健委引研究（180g 菠菜/1000ml 沸水，1 分钟去 43%）；J-STAGE（100°C 30 秒去 >30%，1 分钟去 40%） | 中强（多项独立实验，数值随水量/时间差异大）|
| 胆囊切除后每日脂肪 < 30 g、每日 4–6 餐 | 上海市卫健委《胆囊切除术后，这样吃更健康》：低脂（<30 g/天）、少食多餐（4–6 餐）、饮水 1500–2000 ml | 强（官方科普） |
| 胆囊切除长期每日脂肪 ≤ 50 g、胆固醇 ≤ 300 mg | 全国党媒信息公共平台（引专家） | 中 |
| 「急性风险优先于长期风险」 | **我的工程判断**，不是指南条文。理由是结石绞痛是即时可感知损害，血脂是长期风险 | 弱（需你自己确认） |
| 「单餐脂肪上限比全天总量更重要」 | **我的推断**。上海卫健委只给了全天总量与"少食多餐"，未给单餐上限 | 弱（需你自己确认） |

> 凡是标"弱"的三条，都是我的推理而非文献结论。落地时应当作"待验证假设"，别当成医学依据。

### 10.5 模型不必本地：架构调整

既然只在"代码与数据"层面本地，模型可用云 API，那么：

```
本地：PDF → 结构化（parselabs / docling）→ 指标字典 → 单位换算 → 区间判定 → 约束求解
      ↑ 全部确定性代码，可单测、可复现
脱敏：openmed PII 脱敏（姓名/身份证/医院/日期）
云端：Claude / GPT 只做"把结构化结果与已算好的结论写成中文建议"
落库：本地 SQLite
```

好处：模型质量大幅提升（本地 30B 与云端旗舰在中文医嘱表达上差距明显），代价是要做脱敏与去向审计。**红线仍是：数值和禁忌判断不交给模型。**
