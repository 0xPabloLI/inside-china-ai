# 行业知识层：坐标系与机制研究（#253，2026-11-21）

> **下游票**：`#253`（行业坐标系 Ontology 机制 + 写稿行业定位 + hook 版式库）。本文是该票的**研究切片**——只交证据、基线与机制裁决，不含管线代码改动；落地切片与拆票建议见 §7。
> **配套 L1**：`docs/industry-baselines.md`（写稿时直接查的量级标尺）。
> **证据分级**：`[官方]` 模型卡/官方仓库/论文；`[媒体]` 二手报道或聚合站；`[推断]` 本研究的归纳，不作为事实引用。

---

## 1. 结论

1. **量级标尺必须按「每 token 激活参数」读，不能读总参数。** 2026-11 的中国旗舰 LLM 已到 1.6T–2.8T 总参数量，但每 token 只激活 49B–104B（DeepSeek V4-Pro、Kimi K3、Qwen3.8）。同一代里「总参数大 10 倍」不等于「能力强 10 倍」，写稿把总参数当算力/能力讲会直接误导。
2. **票面「world model 普遍 14B+」需要修正。** 公开可核的头部世界模型是 Genie 3 **11B**、LingBot-World **28B（推理 14B）**；LingBot-World v2 另有 **14B** 与 **1.3B** 两档。1.3B 不是「落后」，而是**端侧/低成本档**，与 14B 是不同产品位，不是同一把尺子的两端。
3. **行业知识层的真实风险不是「没数据」，是「过期数据被当成现值」。** 在知识演化场景里，相似度检索会把旧值和新值一起取出；实测 RAG 在被要求回答时给出**已失效值**的比例是 **15–40%**，且相似度本身无法区分「矛盾」与「改写」（AUROC 0.59，接近随机）。因此不能靠「多写一份 markdown + 定期人肉更新」，要靠**结构化取代**。
4. **机制裁决：键控事实 + 双时态取代 + 懒校验。** 事实以 `(subject, relation, object, asOf, source)` 存储；同 `(subject, relation)` 出现不同 object 时，新事实**取代**旧事实并保留历史（bi-temporal），不靠相似度阈值、不靠 LLM 判断谁新。实体页是这些事实的**视图**，不是第二份真值。
5. **新闻室可复用的两条实践**：① **reground 循环**——已发布页面过期或被新事实推翻时，回炉重写并级联刷新所有提到同一实体的页面；② **写者≠审者**——生产与校验由不同角色完成。这两条正好补上当前「行业定位」缺的门禁。

## 2. 问题：写稿的三处系统性失准

现有 `company-relations.json`（68 实体，`high 17 / mid 20 / low 31`）解决了「怎么称呼、挂什么 hashtag、海外认不认识」，但没有解决「这个模型在这个领域算大还是算小」。三处失准反复出现：

| 失准 | 典型写法 | 为什么错 | 本层怎么治 |
| --- | --- | --- | --- |
| **量级错位** | 「1.3B 的世界模型，只有行业的十分之一」 | 把端侧档与旗舰档放在同一把尺子上；旗舰 Genie 3 也只有 11B | 领域基线带 + 档位（端侧/主流/旗舰），先判档再比数 |
| **突破通胀** | 「参数翻倍，能力跃迁」 | MoE 总参数翻倍但激活不变时，推理成本与能力都可能不变 | 每领域一条「突破判据」，不满足就不写「突破」 |
| **背景假设** | 直接说「Phancy 发布了 Phai-M1」 | 海外观众不认识首次出现的公司 | 首次报道必须带 `who + where + why it matters` 一句定位（已在 `docs/research/company-relations.md` 立规） |

## 3. WS1：2026-11 基线（方法 + 结果）

**取样口径**：截至 2026-11-21，优先取有官方模型卡/权重/论文明示参数的代表模型；闭源模型（Sora、Veo、Genie 4 等）不臆测参数量，只记能力档。完整表见 `docs/industry-baselines.md`，这里只记推导与反例。

| 领域 | 2026-11 旗舰带 | 锚点（总/激活） | 关键反例（写稿最容易踩） |
| --- | --- | --- | --- |
| LLM | 1.6T–2.8T / 49B–104B 激活，1M 上下文 | DeepSeek V4-Pro 1.6T/49B `[官方]`；Kimi K3 2.8T/104B `[官方]`；Qwen3.8 2.4T/95B `[媒体]` | 「671B 就是上一代旗舰」已过期：V3.2 是 671B/37B，2026 年旗舰翻到 T 级 |
| 世界模型 | 10–28B 总，14B 级推理；720p 实时、分钟级记忆 | Genie 3 11B `[媒体]`；LingBot-World 28B/14B `[官方仓库]`；v2 14B 与 1.3B `[官方仓库]` | 「1.3B 落后」错——1.3B 是端侧档；Genie 4（2026-10-27）参数未公开，不能编 |
| 视频生成 | 开源 5B 稠密 ～ 27B/14B MoE；720p@24fps | Wan2.2 T2V/I2V-A14B 27B/14B、TI2V-5B `[官方]` | 把「14B」当总参数：A14B 是**激活** 14B、总 27B |
| VLM | 2B–235B；MoE 30B-A3B / 235B-A22B；256K | Qwen3-VL 全家桶 `[官方论文]` | 用「8B 打不过 235B」当结论：两档服务的是延迟-质量不同取舍 |
| TTS | 0.5B–1.5B；百万小时级训练；9 语种零样本 | CosyVoice 3 0.5B/1.5B `[官方论文]` | 「TTS 也要上 30B」无依据：TTS 的瓶颈在数据/后训练，不在参数量 |
| 全模态 | 30B-A3B 级；文本 119 语种、语音出 10 语种、首包 234ms | Qwen3-Omni-30B-A3B `[官方论文]` | 把「全模态」当「每模态都 SOTA」：官方口径是「不劣化」，不是全面领先 |

**突破判据（写稿可引用的最小集合）**：

- **LLM**：同代基准（MMLU-Pro、LiveCodeBench、长程 agent 任务）出现**跨档提升**，且 1M 上下文下成本显著下降；仅参数变大不算。
- **世界模型**：实时交互的分辨率/帧率/记忆长度任一跨档（如 720p@24fps → 1080p 或分钟级 → 十分钟级），或首次支持可控事件/多智能体。
- **视频生成**：原生音频、1080p、长镜头一致性、物理合理性任一从「演示」变「可交付」；单纯美学提升不算突破。
- **VLM**：OCR/长视频时序 grounding/文档结构理解出现可复现的跨档；「榜单 +1 分」不算。
- **TTS**：零样本跨语种自然度、情感/方言可控、首包延迟 <250ms 三者同时改善才算换代。
- **全模态**：单模型在文本/图像/音频/视频上不劣化，且流式端到端可用；拼四个单模态模型不算。

**方法边界**：闭源模型参数不公开的，只记能力档与时间点；聚合站参数（如 Qwen3.8 2.4T-A95B）标 `[媒体]`，进 L1 表时带来源与日期，超过 90 天未见官方确认即降级为「待核」。

## 4. WS2：为什么「markdown + 定期更新」必然过期

### 4.1 过期是结构问题，不是勤奋问题

`Temporal Validity in Retrieval Memory`（arXiv 2606.26511，2026）给出三个可直接用的实测：

- 知识演化场景下，RAG 在**被要求回答**时输出已失效值的比例 **15–40%**（允许弃答时则靠拒答掩盖）。
- 旧值与新值在嵌入空间几乎同样相似；**矛盾比复述更相似**（value flip 的编辑距离小于真正改写），任何阈值规则的最高精度只有 0.67，AUROC 0.59。
- 解法是**结构化取代**：同 `(subject, relation)` 键下 object 不同即由新事实取代旧事实，写入双时态账本；读路径零 LLM 调用，延迟 ~2.1s。静态知识召回不受损，演化知识准确率 0.20–0.47 → 0.95–1.00。

对我们的含义：行业知识若只写成自由文本段落，写稿时「2026-08 的参数量」和「2026-11 的参数量」会同时被检索出来，模型没有时间感。**必须以实体+关系为键**，并让新值显式退役旧值。

### 4.2 新闻室已经在做的事

- **新闻知识图谱**（ACM Computing Surveys 2022 综述）：JKP 的典型结构是 archive + ontology + knowledge base；本体定义词表与关系，知识库存语义化事实，并用 belief-base revision 检测/消解不一致 `[官方综述]`。
- **reground 循环**（llm-wiki-newsroom，2026）：已发布页面过期或被新事实推翻时回炉重写；摄入一篇新文档会**级联刷新**它提到的 10–15 个实体/概念页 `[媒体/开源实现]`。
- **矛盾追踪**：冲突在全局摘要、主题页、原始问题三层记录，而不是被静默覆盖 `[媒体/开源实现]`。
- **写者≠审者**：生产页面的 agent 不做最终审校，审校由独立角色完成 `[媒体/开源实现]`。
- **新鲜度即元数据**（Atlan，2026）：过期是运营问题；可行做法是跟踪「源最后修改时间 vs 索引最后摄入时间」，并对被高频引用的事实加重校验 `[媒体]`。
- **改动的语义检测**（OwlerLite，arXiv 2601.17824，2026）：按语义变化而非页面 diff 决定是否重索引，检索时把 recency 作为特征 `[官方论文]`。

### 4.3 结论：知识层长什么样

```
事实（fact） = (subject, relation, object, asOf, source, confidence, status)
  status ∈ {current, superseded, disputed}
实体（entity）= 事实的视图：identity / relations / products / people / awareness
页面（page）  = 给人读的渲染，不存真值；每次渲染带 lastVerified
```

- **写**：新事实入账 → 同键不同值自动把旧值置 `superseded`（不删除，保留历史与来源）→ 级联标记受影响的实体页。
- **读**：写稿只取 `current`；涉及数字时必须带 `asOf` 与来源；`asOf` 超过新鲜度预算（默认 90 天，快速演化领域 30 天）时触发**懒校验**，校验未完成前写稿只能用「截至 X 月」措辞，不能写现在时。
- **审**：写稿 Agent 产出的行业定位句，由独立校验步骤比对事实账本；不一致即 `disputed`，进 HITL。

## 5. 数据与消费：最小可用形态

**存储**：`scripts/short-video/lib/data/industry-knowledge.json`（v1，单文件，事实数组 + 实体索引）。不引入图数据库：规模是百级实体、千级事实，JSON + 索引足够；上 RDF/SPARQL 只会把维护成本转嫁给写稿流程。

**关系词表（v1 只开 8 个，可扩展）**：

| relation | 例子 | 消费点 |
| --- | --- | --- |
| `has_model` | `phancy → phai` | 实体卡、caption 品牌白名单 |
| `model_domain` | `phai_m1 → video_generation` | 领域基线查表 |
| `model_scale` | `kimi_k3 → {total: 2.8T, active: 104B}` | 量级句 |
| `release_date` | `phai_m1 → 2026-11` | 「最新/首个」判据 |
| `capability_marker` | `genie3 → realtime_720p_24fps` | 突破判据 |
| `listed_on` | `phancy → HKEX 6682` | 背景句 |
| `overseas_awareness` | `phancy → low` | 是否讲背景 |
| `competitive_position` | `qwen3vl → frontier_band` | 「旗舰/主流/端侧」档位 |

**消费（三个读点，不做第四个）**：

1. **Stage 3 写稿**：注入「本 Pack 实体的 current 事实 + 领域基线带 + 是否首次报道」，作为结构化上下文，不注入整份知识库。
2. **量级句校验**：写稿产出的数字句与 `model_scale` 比对，总/激活混用、档位错位直接标红。
3. **发布前事实闸**：抽取旁白/字幕中的数字与实体，断言必须在 `current` 事实里可溯源；`asOf` 超预算且未校验的，阻断并转人工。

**防过期的运营规则**：

- 每张新 Pack 开工时，只对该 Pack 涉及实体做一次懒校验（低成本、局部）。
- 每月对 `high` 认知度实体与旗舰档模型做一次抽样复核；每季度全量过一遍 `current` 事实的 `asOf`。
- 任一事实被新来源推翻时，旧值保留为 `superseded` 并记录 `supersededBy`，禁止直接改写——否则无法回答「为什么上期说 1.6T」。

## 6. hook 版式库：现状与缺口

**现状**：视觉层已有三种可切换版式——`HookScene` 的 **number-led**（大数字）、**claim-led**（主张 + 揭示句）、`HookMediaLed`（`layout: "media-led"`，图即证据）。也就是说「≥3 可切换版式」在渲染层**已经成立**。

**真正的缺口在编辑层**：

1. 没有「选哪种」的判据。当前靠写稿 Agent 手感，导致连续几期都用 number-led。
2. 没有跨期反重复。版式轮换不是审美问题，是**观众疲劳**问题；同一账号连续三条同版式，完播率会掉。
3. 没有和论证结构绑定。版式库只换皮、不改论证（C7 的约束）：number-led 要求有一个真能撑住首屏的数字；claim-led 要求主张可在一句内证伪；media-led 要求画面本身是证据，不是氛围图。

**提议的选版规则（进 Stage 3，不新建视觉）**：

| 版式 | 何时用 | 硬前提 | 禁用 |
| --- | --- | --- | --- |
| number-led | 开场事实是一个**跨档数字**（如 2.8T、1M 上下文、234ms） | 数字有 `current` 事实且带 `asOf` | 数字只是「大约/数十倍」；数字属于背景而非新闻点 |
| claim-led | 新闻点是一句可证伪的判断（「首个开源 3T 级」「不降级」） | 主张在正文 30 秒内被证据兑现 | 主张需要两段以上铺垫才能成立 |
| media-led | 画面即证据（官方 demo、模型卡截图、实拍对比） | 素材 provenance 可追、非装饰图 | 图只是氛围/品牌 logo；图文无互证 |

**反重复**：读取最近 3 条已发布 Pack 的 hook 版式，同版式连用 ≥3 次即强制换版式或给出「为什么必须重复」的一句理由。

## 7. 落地切片（下一刀）

研究切片已闭环，实施建议拆成三张可独立交付的票（**不替用户开票**，等确认后再建）：

1. **S1 数据层**：`industry-knowledge.json` v1 + schema 校验 + 迁移脚本把现有 `company-relations.json` 的实体/模型/认知度灌入；验收：68 实体全部可解析，事实带 `asOf/source`，`superseded` 可回放。
2. **S2 消费层**：Stage 3 注入块 + 量级句校验 + 发布前事实闸；验收：总/激活混用、档位错位、超期未校验三类各有一个红灯用例。
3. **S3 编辑层**：hook 版式选版判据 + 跨期反重复；验收：三种版式各有一条正例/反例 Pack，连用 3 次触发换版式建议。

**顺序**：S1 → S2 → S3。S2 依赖 S1 的事实键；S3 只依赖已发布记录，可与 S1 并行，但建议排在 S2 后以免同时改 Stage 3。

## 8. 不能承诺

- 不承诺覆盖闭源模型的真实参数量：Sora、Veo、Genie 4 不公开，表里只记能力档。
- 不承诺「一次录入永久正确」：本机制的目标是把过期从**静默错误**变成**可见的 `asOf` 与 `disputed`**，不是消灭过期。
- 不承诺用本层替代写稿判断：基线只给「这个数在该领域算什么档」，新闻价值判断仍由写稿与 HITL 负责。
- 不承诺自动修所有矛盾：结构化取代只处理同键不同值；跨实体、跨单位的矛盾仍需人工裁决。
