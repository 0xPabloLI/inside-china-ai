# 视频背景视觉承载审查结论

**审查日期：2026-08-21**  
**状态：已确认存在策略落地缺口**  
**作者：Manus AI**

## 结论

当前短视频管线**尚未落实**“全程保持经过设计的视觉承载，但不机械地给每个场景填充独立图片或视频”的背景策略。现有实现具备外部媒体渲染、素材推荐和品牌化 CSS 模板三项基础能力，但这些能力是可选的，且没有被分镜契约或 MRL-2 验证规则统一约束。因此，内容并非出现黑屏或完全无视觉状态；相反，模板会提供网格、光晕、扫描线与品牌框架。但绝大多数场景缺少主题相关的图片或视频，也缺少对“为什么应使用模板、极简画面或留白”的显式记录。[1] [2]

> **决策：视频应要求每个场景都有明确的视觉意图，而不是要求每个场景都必须配置独立的背景图片或视频。** 强关联事实、演示和案例应优先使用真实媒体；解释、数据、结论和情绪停顿可采用低干扰模板、静帧、局部特写或有意留白。

## 审查范围与方法

本次审查统计 `scripts/short-video/content/` 下的生产 `scene-data.mjs`，排除 `_test-fixtures`。统计口径是每个场景是否显式声明 `media` 字段；这衡量的是与内容相关的图片或视频覆盖，**不**否认各视觉组件本身仍会绘制品牌化 CSS 背景。

| 审查项目                |     结果 | 含义                                                |
| ----------------------- | -------: | --------------------------------------------------- |
| 生产分镜文件            |       12 | 所有现有生产 `scene-data.mjs`，不含测试夹具         |
| 场景总数                |      111 | 以 `visualType` 声明计数                            |
| 显式声明 `media` 的场景 |        9 | 仅 9 个场景配置图片或视频背景                       |
| 显式媒体覆盖率          | **8.1%** | `9 ÷ 111 × 100`，低于“重要场景用相关视觉承接”的目标 |
| 媒体全覆盖的分镜文件    |        0 | 没有任何一条现有视频为所有场景声明 `media`          |

现有显式媒体集中于 `sensetime-latest` 的 5 个叙事场景与 `unitree` 的 4 个场景；其余 10 个生产分镜文件均未声明场景媒体。`sensetime-latest` 中的注释也明确将钩子与 CTA 继续交给共享模板，而非使用主题相关媒体。[3]

## 已具备能力

当前架构并不需要从零开始。`SceneData.media` 已是支持图片、视频、遮罩、裁切、动画和音量的可选字段；`MediaBackground` 组件能够正确渲染图片或视频并提供透明度与转场控制。[2] [4]

| 能力               | 当前状态       | 审查判断                                                                                     |
| ------------------ | -------------- | -------------------------------------------------------------------------------------------- |
| 图片／视频背景渲染 | 已实现         | 可按场景渲染图片或视频，并支持覆盖层与运动预设。[2]                                          |
| 默认品牌视觉       | 已实现         | 无媒体时仍有网格、光晕、扫描线、品牌栏和边框，因此不是空白或黑屏。[5]                        |
| 素材推荐与媒体补丁 | 已实现但非强制 | 素材工具会推荐可分配媒体，但明确不自动改写 `scene-data`；人工审核后才填入媒体字段。[6]       |
| 关键媒体覆盖规则   | 未实现         | 分镜媒体为可选字段，MRL-2 未检查视觉意图或相关媒体覆盖。[1] [4]                              |
| 例外语义           | 部分存在但过粗 | `cta`、`data`、`stat-reveal` 被自动素材分配排除，但没有记录它们选择模板或留白的叙事理由。[6] |

## 缺口判断

问题不是“要不要让每一秒都有图片或视频”，而是**没有一个可验证的场景级视觉决策**。这会导致素材是否配置完全依赖创作者临时判断：钩子可能继续采用通用模板；需要证据的叙事段也可能没有真实画面；数据或结论段虽适合弱化背景，却无法区分“主动留白”与“没有做视觉设计”。

| 缺口                     | 证据                                                                                   | 对内容的影响                                               |
| ------------------------ | -------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| 视觉意图未进入场景契约   | `SceneData` 仅有可选的 `media`，没有视觉意图、背景类型或例外理由字段。[4]              | 无法在创作或审查时区分证据画面、解释性模板与有意留白。     |
| 钩子没有媒体要求         | MRL-2 只要求第一场景的 `visualType` 为 `hook`，不要求首帧使用与主题直接相关的视觉。[1] | 前 3 秒可能缺少足够明确的观看理由。                        |
| MRL-2 不验证视觉层级     | 当前检查覆盖场景数、时长、Hook、CTA、数据一致性等，不覆盖背景与信息层级匹配。[1]       | 视觉质量只能留到成片人工审阅，不能在分镜阶段提前发现缺口。 |
| 自动素材推荐未闭环       | 素材工具仅生成建议和补丁，不自动写回分镜。[6]                                          | 已找到的高质量素材不一定会转化为视频中的视觉承接。         |
| 例外规则只按模板类型划分 | `cta`、`data`、`stat-reveal` 被统一排除媒体，而非由每段信息密度和叙事任务决定。[6]     | 可能错误地弱化本该使用图表、截图或证据画面的数据场景。     |

## 建议的目标状态

后续改进应把“视觉承载”定义为每一场景必须声明的创作决定，而非把“有外部媒体”变成死板 KPI。建议分镜层区分下列视觉意图；是否要求外部媒体由意图决定。

| 视觉意图    | 默认视觉处理                         | 外部媒体期望             | 适用场景                           |
| ----------- | ------------------------------------ | ------------------------ | ---------------------------------- |
| `evidence`  | 主题相关的图像、视频、录屏或数据截图 | 应配置，除非记录阻断原因 | 新闻事实、案例、产品演示、引用来源 |
| `explain`   | 低动势 B-roll 或品牌化解释模板       | 可选                     | 背景补充、概念拆解、普通叙事       |
| `emphasize` | 极简底色、局部特写、静帧或大字卡     | 通常不需要               | 关键数字、结论、金句               |
| `pause`     | 有意留白或低干扰静态背景             | 不需要                   | 情绪转折、复杂信息消化、免责声明   |
| `cta`       | 标准化结尾模板                       | 不需要                   | CTA 与品牌收束                     |

这一定义同时保留“全程有视觉状态”的优点，并保护高信息密度段落的可读性。它也使媒体覆盖变成可按意图衡量的质量指标：应关注 `evidence` 场景的相关媒体覆盖和全体场景的视觉意图声明完整率，而不是盲目追求所有场景的媒体覆盖率。

## 后续工作建议

建议通过一个独立的实现 Issue 建立场景级视觉意图契约、补充 MRL-2 的可审计检查，并让素材推荐结果能在人工审核后形成可追溯的分镜决策。该 Issue 必须保留 `data`、`stat-reveal` 和 `cta` 使用低干扰模板的合法性，避免把“背景全覆盖”误实现为“每一秒都高信息量”。
