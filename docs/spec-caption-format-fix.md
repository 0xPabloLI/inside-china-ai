# Spec: TikTok Caption Format Fix

## Problem Statement

TikTok captions are a single text field (≤2200 chars) — there is no separate "title" field. The current `generate-caption.mjs` outputs `title\n\ndescription\n\nhashtags` with a title separator that doesn't exist in TikTok. Additionally:

1. **Comment hook is generated by mechanical templates** — produces nonsensical output like "382 million or 382M — which surprised you more?" (same number in two formats). Fixed templates cannot understand video semantics.
2. **Hashtag matching is keyword-based on full voiceover text** — matches competitor companies mentioned in passing (e.g., `#alibaba` `#tencent` for a ByteDance video). Not precision-targeted.
3. **Caption output is global** — `output/tiktok-caption.txt` gets overwritten by each content, causing cross-content collision.

## Solution

### Fix A: Caption Format (One-Block)

Merge title sentence into description as the opening hook. Output: `{hook sentence}\n{description body}\n\n{hashtags}`. No title separator. User copies the whole block into TikTok's single text field.

### Fix B: Comment Hook via AITL

Delete all template logic (`COMMENT_HOOK_TEMPLATES`, `extractEntities` number extraction, `deriveCommentHook` template fallback). Comment hook is generated by Agent during scene-data production (AITL stage), written to `metadata.commentHook` in scene-data. `derivePinnedComment` simply reads `metadata.commentHook` — if present, outputs it; if absent, returns empty string.

### Fix C: Hashtag Precision

Change hashtag derivation from full-text keyword matching to `meta.keyEntities` lookup only. `ENTITY_HASHTAG_MAP` becomes a company-name → hashtag lookup table. Source of companies: `meta.keyEntities.companies` only. Add missing mappings: `doubao` → `#doubao`, `feishu`/`lark` → `#feishu`. Remove voiceover full-text entity scanning.

### Fix D: Per-Content Output

`generate-caption.mjs` writes to `output/<contentDir>/tiktok-caption.txt` and `output/<contentDir>/tiktok-metadata.json` instead of global `output/`.

## User Stories

1. As a video publisher, I want the caption to be one block I can copy-paste into TikTok, so that I don't have to manually merge title + description + hashtags.
2. As a video publisher, I want comment hooks to be semantically meaningful, so that they actually encourage viewers to comment.
3. As a video publisher, I want hashtags to match the video's main subject (not competitors mentioned in passing), so that TikTok shows the video to the right audience.
4. As a video publisher, I want each content's caption saved separately, so that generating a new video doesn't overwrite the previous caption.
5. As a pipeline maintainer, I want `caption-utils.mjs` tested for all these scenarios, so that regressions are caught before publishing.

## Implementation Decisions

### Fix A: Caption Format

- **`caption-utils.mjs` `deriveDescription`**: The title hook sentence becomes the first line of description. `deriveTitle` is still called (for metadata JSON and SEO), but `generate-caption.mjs` merges it into the description block.
- **`generate-caption.mjs`**: Caption text format changes from `title\n\ndescription\n\nhashtags` to `description\n\nhashtags` (title hook is already the first line of description).

### Fix B: Comment Hook via AITL

- **`caption-utils.mjs`**: Delete `COMMENT_HOOK_TEMPLATES` array, `extractEntities` function (number/company extraction for hooks), and `deriveCommentHook` template logic. `derivePinnedComment` simplified to: read `metadata.commentHook`, return it (or empty string if not set). Description no longer appends comment hook.
- **Agent workflow**: When producing scene-data, Agent generates a meaningful comment question based on video semantics and writes it to `metadata.commentHook` in scene-data.mjs.
- **`deriveDescription`**: Remove comment hook appending. Description = voiceover-derived body + CTA only.

### Fix C: Hashtag Precision

- **`caption-utils.mjs` `deriveHashtags`**: Remove full-text `ENTITY_HASHTAG_MAP` keyword scanning from voiceover. Instead, read `meta.keyEntities.companies` (passed via metadata), look up each company in `ENTITY_HASHTAG_MAP` to find its hashtag. If no match, skip (don't pad with unrelated tags). `#ainews` + `#chinaai` always present. Pad with `#technews` if < 3.
- **`ENTITY_HASHTAG_MAP`**: Add `doubao` → `#doubao`, `feishu`/`lark` → `#feishu`. Retain existing entries for other companies.
- **`generate-caption.mjs`**: Pass `meta.keyEntities.companies` to `deriveHashtags` via metadata.

### Fix D: Per-Content Output

- **`generate-caption.mjs`**: When `--content <dir>` is passed, write to `output/<dir>/tiktok-caption.txt` and `output/<dir>/tiktok-metadata.json`. Without `--content`, keep current global output (backward compat).

## Testing Decisions

- **Fix A tests**: Verify caption text has no `\n\ntitle\n\n` separator. Verify first line of description is the hook sentence.
- **Fix B tests**: Verify `derivePinnedComment` returns `metadata.commentHook` when set. Verify returns empty string when not set. Verify description does NOT contain comment hook.
- **Fix C tests**: Verify hashtags only come from `keyEntities.companies` lookup. Verify `#doubao` matched for doubao content. Verify `#alibaba` NOT matched when alibaba is only in voiceover (not in keyEntities). Verify `#ainews` + `#chinaai` always present.
- **Fix D tests**: No unit test needed (file path logic, covered by integration).
- **Prior art**: existing `caption-utils.test.mjs` (35 tests) is the seam. Update tests that break from changes, add new tests for new behavior.

## Out of Scope

- Installing local LLM or calling external API for comment hook generation (Agent handles this in AITL).
- Changing `deriveTitle` logic (still used for metadata.json SEO).
- TikTok API publishing automation (ISSUE-01, separate scope).
- Hashtag trend research / Creative Center integration (existing, unchanged).

## Further Notes

- "AITL" (Agent-in-the-Loop) is the project's term for Agent participation in pipeline stages. The Agent generates comment hooks during scene-data production, not during a separate "HITL" checkpoint. The term HITL is deprecated in favor of AITL.
- The `ENTITY_HASHTAG_MAP` keyword lists for each entry become irrelevant — only the company name (key) and hashtag (value) matter. The keywords array can be removed or kept for documentation but is no longer used for matching.
