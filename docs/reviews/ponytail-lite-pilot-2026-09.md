### 字段口径

- **规则是否到达（evidence）**：本次任务中规则是否被实际读取或引用，以及证据来源（如"日志出现选择顺序推理"、"无任何相关推理"）。**没有 evidence 就填"无"，不要推测**。此栏用于区分"规则无效"与"规则没被读到"——两种情况在 finding 数上表现相同（复核裁决 Q5）。
- **A-lite 选择及放弃的替代**：最终走了哪一档、最初倾向是什么、是否因规则改变了选择。未改变填"未改变选择"。
- **B-lite finding**：标注 **独有**（smell 基线不会报）/ **重复**（与 Fowler 基线重叠）/ **误报**（报告了不存在行为等价替代的项），以及接受或拒绝的理由。
- **spec parity**：实现是否完整满足 spec 与 ticket acceptance criteria，有无功能缺失。**不满足即触发 hard gate**。
- **返工**：因选错 seam、漏掉调用方或按 finding 修改而重做的次数与原因（含"因 B-lite 误报导致返工"）。
- **D（bug？触发？）**：是否 bug 任务；若是，是否执行了根因搜索、调用方是否共享同一不变量、事后是否验证该判断正确。
- **实际收益（定性）**：与同类任务的比较——代码量、文件数、耗时、复杂度，填"更少/相当/更多 + 依据"。不填比例（5 个任务不支持量化）。

## 裁决（试点期满填写，逐条独立，不捆绑）

### Hard gate（触发即撤销对应条目，不等期满）

出现可归因于 A-lite / D 的任一项：

1. 安全回归；
2. 正确性回归；
3. **spec parity 缺失**（实现未满足 spec 或 acceptance criteria）；
4. **测试被省略或弱化**（以"少写代码"为由削减验证义务）；
5. **可访问性回归**；
6. 错误处理回归（尤其信任边界校验、防数据丢失处理）。

### 保留门槛（三条各自独立判定，每条需**同时满足**全部条件才保留）

> **措辞说明（复核 R2）**：本文件与提案 v6 起一律用"**保留**"而非"转正"。理由：5 个任务 + 正向定性证据支持的是"继续保留这三条规则"这个**低成本决定**，支持不了任何收益量级声明。**"保留"不等于"已采纳上游报告的效果量级"**——后者需要本试点无法提供的样本量（见"范围"段）。期满结论中不得出现收益比例、效率提升一类表述。

1. **交付确认**：≥80% 的任务在"规则是否到达"栏有正向 evidence。未达标说明未验证的是送达而非规则本身——先解决送达再谈保留。
2. **A-lite**：至少一次实际改变实现选择，**且该次改变带来正向收益**（更少代码、更少文件、更少返工，且 spec parity 无损）。**仅改变选择不算**——改变可能更好，也可能更差。
3. **B-lite**：至少一个**独有**且被接受的 finding，且**误报未造成返工**。
4. **D**：至少一个 bug 任务实际触发，且"调用方是否共享同一不变量"的判断事后被验证为正确。
5. **样本**：≥5 个任务，且上述正向证据齐备。

### 未达门槛时的处置

- **有正向证据但不充分**（部分条件达标）：延长窗口，最多再 5 个任务；延长后仍不足则标记"未验证"。
- **无正向证据但未触发 hard gate**：标记"未验证"。
- **"未验证"的解读**：不构成采纳证据，也不构成否定证据——它表示本次试点没有能力回答该条是否有价值。
- **零 finding 的解读**：先查"规则是否到达"栏；未到达则不能作为规则的判断依据，已到达则说明代码本已精简或与 smell 基线重复。
- **送达升级触发条件（复核 R5）**：若试点前 2–3 个任务的交付确认（"规则是否到达"栏正向 evidence）**<80%**，说明问题是送达而非规则本身——届时再评估为当前宿主（Factory/Droid）配置 `SessionStart` / `UserPromptSubmit` 钩子（配置与事件见复核材料 §6.3）。此前不上钩子。

### 期满裁决

对 A-lite / B-lite / D 各出一条结论，取值限定为以下五种（**复核 R2：删除原"转正"档，改为"保留"**）：

| 结论           | 含义                                                   | 后续动作                                                                     |
| -------------- | ------------------------------------------------------ | ---------------------------------------------------------------------------- |
| **保留**       | 满足保留门槛，且未触发 hard gate                       | 去掉"试点"标注，规则转为长期。**不得附带任何收益量级声明**——本试点不支持量化 |
| **延长后再裁** | 有正向证据但不充分，或交付确认 <80%                    | 延长窗口，最多再 5 个任务                                                    |
| **修订后再试** | 证据指向规则文本有问题（如被误读、措辞歧义）但方向可用 | 改文本，重新计数                                                             |
| **撤销**       | 触发 hard gate，或出现反向证据                         | 回退 `implementation-workflow.md` §6/§8 对应增补行                           |
| **未验证**     | 无正向证据也未触发 hard gate                           | 保留试点标注，待更大样本或换验证方式                                         |

一条有效不得带动其余两条保留，一条无效也不否定其余两条。撤销只回退对应增补行，不株连其余两条。
